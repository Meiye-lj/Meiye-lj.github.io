Current Research Problem

Trustworthy Execution of Autonomous Software R&D

When an autonomous development agent says “done”, what evidence justifies trusting the execution—and how can that execution remain efficient, recoverable, and under appropriate human control?

The goal is not to directly prove end-to-end software correctness. Instead, I focus on whether the execution process is supported by fresh, scoped, and traceable evidence: whether the observed behavior is valid, whether a completion claim is justified by that evidence, how much of the change has actually been verified, and how the system should react when evidence is incomplete or contradictory.
01

Unified Modeling of Task–Behavior–State–Evidence

Represent what the agent is asked to do, what it actually does, how the software state changes, and which observable evidence supports each claim.

02

Efficient Autonomous Execution under Trust Constraints

Reduce feedback latency, redundant validation, rework, and search cost while preserving evidence freshness, scope, and correctness constraints.

03

Failure Diagnosis, Attribution, and Recovery

Identify why an autonomous task failed, distinguish environment/tool/model causes, and select repair, rollback, retry, or re-planning actions with verifiable outcomes.

04

Human-in-the-Loop Dynamic Autonomy

Adapt the level of autonomy to uncertainty and risk, escalating to humans when evidence is insufficient and returning control to agents when the state becomes verifiable.

NSFC Young Scientists Fund

Systematic Acceleration of Complex Software Builds

复杂软件构建的系统加速研究

Build Systems Performance Incremental Build

This project studies build acceleration as a system-level problem rather than a single optimization technique. It establishes a unified observation framework for repeated builds and asks where time is fundamentally lost, which losses can be removed, and what performance ceiling remains after optimization.

L1

Cross-configuration reuse and ordering

Model reuse boundaries, rebuild closures, and ordering sensitivity across configurations to reduce redundant work while preserving correctness.

L2

Waiting loss and parallelism within one build

Quantify scheduling stalls, idle intervals, resource contention, and unrealized parallelism to explain avoidable latency in a single build.

L3

Critical paths, long chains, and acceleration limits

Identify structural long chains in the build DAG and estimate the reachable speedup ceiling after removable waiting and redundant work are eliminated.
